# mention-agent

Агент мониторинга упоминаний бренда на LangGraph: каскад моделей, tool-calling,
structured output с валидацией и human-in-the-loop.

> Черновик README после вечера 1. Полная версия с архитектурой, метриками и сценарием демо — после вечера 2.

## Запуск на локальных моделях (бесплатно)

По умолчанию агент работает через [Ollama](https://ollama.com) на вашем компьютере, ключ API не нужен.

```bash
# 1. Ollama: установить с ollama.com (или `docker compose up -d`) и скачать модели
ollama pull qwen2.5:3b     # дешёвая модель: триаж (~2 ГБ)
ollama pull qwen2.5:7b     # сильная модель: tool-calling и план (~4.7 ГБ)

# 2. Проект
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest                     # тесты (офлайн, модели не нужны)
python cli.py              # прогон на локальных моделях
```

Если Ollama не запущена или модели не скачаны, `cli.py` сразу скажет, какую команду выполнить.

**Железо.** qwen2.5:7b нужно около 6 ГБ видеопамяти или 8 ГБ ОЗУ на CPU. На CPU прогон 14 упоминаний
занимает несколько минут: так видно, зачем нужен каскад. Если машина слабая, поставьте одну модель на оба уровня:
`STRONG_MODEL=qwen2.5:3b`. Другие модели с поддержкой tool-calling: `llama3.1:8b`, `qwen2.5:14b`.

**Контекст.** Если модель «забывает» инструкции, увеличьте окно контекста Ollama:
`OLLAMA_CONTEXT_LENGTH=8192 ollama serve`.

## Быстрое демо (3–5 минут)

Полный прогон 14 упоминаний на CPU занимает около 25 минут. Для показа есть короткий набор
`data/mentions_demo.json` из 6 упоминаний. В нём есть все ветки каскада: спам (отсеивают правила),
благодарность (закрывает дешёвая модель), жалобы на доставку, оплату и качество (сильная модель + инструменты)
и утечка данных (ручная проверка).

```bash
STRONG_MODEL=qwen2.5:3b python cli.py --file data/mentions_demo.json
```

Пока идёт обработка, в stderr печатается ход: `[m03] триаж: payment, high…`, `[m03] сильная модель вызывает: …`.
`--quiet` отключает эти строки, `--json` их не смешивает с JSON.

**Какую сильную модель брать.** Замеры на Mac Intel (16 ГБ ОЗУ, только CPU), 6 упоминаний:

| Сильная модель | Время | Качество планов |
|---|---|---|
| `qwen2.5:3b` | ~4 мин | маршрутизация та же, но инструменты вызывает реже (часто пропускает плейбук), шаги проще и иногда повторяются |
| `qwen2.5:7b` | ~15 мин | проходит все инструменты, план опирается на правила плейбука |

Для живого демо на таком Mac берите `qwen2.5:3b`. Прогон на `qwen2.5:7b` лучше запустить заранее и
показать как сравнение качества (`python cli.py --file data/mentions_demo.json --json > demo_7b.json`).
На машине с GPU или Apple Silicon 7b укладывается в демо и без этого.

Для показа за ~90 секунд есть ещё более короткий набор `data/mentions_live.json` (4 упоминания) и
прогрев моделей `python cli.py --warmup`. Подготовка и сценарий — в [DEMO.md](DEMO.md).

## Настройки

Все параметры задаются переменными окружения, пример в `.env.example` (`set -a; source .env; set +a`).

| Переменная | По умолчанию | Что это |
|---|---|---|
| `LLM_PROVIDER` | `ollama` | `ollama`, `openai` (внешний API) или `fake` (офлайн-заглушка) |
| `OLLAMA_BASE_URL` | `http://localhost:11434/v1` | адрес Ollama, можно указать другой компьютер в сети |
| `CHEAP_MODEL` / `STRONG_MODEL` | `qwen2.5:3b` / `qwen2.5:7b` | модели двух уровней каскада |
| `LLM_TIMEOUT` | `300` | секунд на один запрос к модели |
| `REVIEW_THRESHOLD` | `0.7` | ниже этой уверенности — ручная проверка |
| `MAX_TOOL_STEPS` | `4` | лимит шагов tool-calling |

Переключиться на внешний API без изменения кода: `LLM_PROVIDER=openai OPENAI_API_KEY=sk-... python cli.py`
(`OPENAI_BASE_URL` для OpenRouter и других совместимых сервисов).

**Метрики каскада.** С локальными моделями деньги не тратятся, поэтому отчёт показывает экономию времени:
сколько секунд работали модели и сколько ушло бы, если бы каждое упоминание шло на сильную модель.
С внешним API дополнительно считается стоимость.

**Маленькие модели.** Локальные модели иногда оборачивают JSON в ```` ```json ```` или пишут вызов инструмента
текстом вместо `tool_calls`. Клиент это распознаёт (`agent/llm.py`), а всё остальное по-прежнему проходит
строгую валидацию Pydantic с одним ретраем и ручной проверкой при сбое.

## Как устроено

1. **Префильтр (бесплатно):** дубли, спам, короткие тексты, не про бренд.
2. **Триаж (дешёвая модель):** тема, тональность, важность, уверенность → JSON по схеме.
3. **Маршрутизация:** позитив и неважное при высокой уверенности закрываются сразу; жалобы и всё, в чём дешёвая модель не уверена, уходят дальше.
4. **Investigate (сильная модель + инструменты):** ищет похожие упоминания, правила плейбука, факты о компании. Цикл ограничен `MAX_TOOL_STEPS`.
5. **Plan (сильная модель):** план реакции по Pydantic-схеме, проверка раздела плейбука, один ретрай с текстом ошибки.
6. **Review (правила):** низкая уверенность, юридические риски и утечки, сбой валидации или лимит инструментов → ручная проверка.
